# Numbers and Precision

## **Primitives: Int, Double, Float** {#primitives-numbers}

*   **int**: 32-bit signed integer. Fast, used for counting and whole numbers.
*   **double**: 64-bit floating point. The default for decimals.
*   **float**: 32-bit floating point. Uses less memory but is less precise than double. Requires an `f` suffix (e.g., `3.14f`).

---

## **Common Floating Point Errors** {#floating-point-errors}

**The Problem**: Computers represent numbers in binary. Some decimal numbers (like 0.1) cannot be represented exactly in binary, leading to tiny rounding errors.

```java
double result = 0.1 + 0.2;
System.out.println(result); // Prints: 0.30000000000000004
System.out.println(result == 0.3); // Prints: false
```

**The Fixes**:
```java
double a = 0.1 + 0.2;
double b = 0.3;
double epsilon = 0.000001;

if (Math.abs(a - b) < epsilon) {
    System.out.println("They are effectively equal.");
}
```

## **BigDecimal** {#bigdecimal}

`BigDecimal` provides absolute precision for decimal arithmetic. It is essential for banking, tax, and scientific calculations.

*   **Immutability**: Like Strings, `BigDecimal` objects are immutable. Operations lead to new objects.
*   **Creation**: Always use the **String constructor** to avoid precision issues during creation.

```java
// ❌ Bad: precision loss happens BEFORE BigDecimal is even created
BigDecimal bad = new BigDecimal(0.1); 

// ✅ Good: exact representation
BigDecimal good = new BigDecimal("0.1"); 

BigDecimal price = new BigDecimal("10.00");
BigDecimal tax = new BigDecimal("0.05");

// Comparison: ALWAYS use .compareTo()
// .equals() returns FALSE if the scale is different (e.g., 1.0 vs 1.00)
BigDecimal a = new BigDecimal("1.0");
BigDecimal b = new BigDecimal("1.00");

System.out.println(a.equals(b));    // false (different scale)
System.out.println(a.compareTo(b)); // 0 (they are numerically equal)

// Rounding: Important for division
BigDecimal result = new BigDecimal("10").divide(new BigDecimal("3"), 2, RoundingMode.HALF_UP); // 3.33
```
